# Observability core

Implements the trace contract in `docs/spec.md` section 8, with injected
OpenTelemetry providers and no import-time clients or global provider replacement.
Azure SDK calls are confined to `src/observability_core/infrastructure/` behind
`TraceExportAdapter`. Instrumentation dependencies are pinned in `pyproject.toml`;
the GenAI attribute names below are the contract for that pinned version.

## Integration

At application lifespan startup, await `start_application_insights(settings)` from
`accelerator.observability_core.infrastructure.application_insights`. It returns
`(telemetry, adapter)`. Inject `telemetry` into workflow/tool services and wrap the
ASGI app with `TracingMiddleware(app, telemetry)`. At lifespan shutdown, await
`stop_application_insights(telemetry, adapter)`. Initialization and shutdown run in
worker threads; export uses `BatchSpanProcessor`, never synchronous network I/O
on the request path. A single adapter owns one exporter.

Use `ApplicationInsightsSettings()` to load `FDE_TELEMETRY_SERVICE_NAME` (required)
and `FDE_TELEMETRY_MANAGED_IDENTITY_CLIENT_ID` (optional for a user-assigned
identity). The Azure exporter reads its destination from the deployment-injected
`APPLICATIONINSIGHTS_CONNECTION_STRING` environment variable. No connection
string, credential, or key belongs in source or checked-in configuration.
Authentication always uses `ManagedIdentityCredential`, not a client secret,
developer login, or key-auth fallback. Disable local authentication on the
Application Insights resource and grant the identity the **Monitoring Metrics
Publisher** role. Missing destination or invalid settings fail startup.

The adapter uses `ApplicationInsightsSampler(1.0)` (full sampling). Offline disk
retry storage is disabled. The SDK reports asynchronous export failures through
its standard logging; monitor those logs and check `telemetry.force_flush()`
before expecting a completed batch. Run flush/shutdown off the event loop.

```python
from accelerator.observability_core import SpanAttributes

# Called within the HTTP middleware's current request context.
with telemetry.span("authz.resolve_scope"):
    context = await resolve_scope()
with telemetry.span("workflow", name="answer"):
    with telemetry.span(
        "retrieval.search",
        attributes=SpanAttributes(filter_fields=("scope_id",), top_k=5),
    ):
        results = await search(context)
    with telemetry.span(
        "retrieval.sufficiency",
        attributes=SpanAttributes(decision="sufficient", reason_code="enough_evidence"),
    ):
        pass
    with telemetry.span("gen_ai.chat", attributes=SpanAttributes(model="gpt-4.1")):
        answer = await generate(results)
    with telemetry.span(
        "tool", name="lookup", attributes=SpanAttributes(risk="read", outcome="success")
    ):
        pass
    with telemetry.span("approval", name="approved"):
        pass
    with telemetry.span("citations.validate", attributes=SpanAttributes(valid=True)):
        pass
```

The example illustrates span placement, not sufficiency or approval policy.
Record actual decisions/counts/tokens, not assumed success; emit only spans for
operations actually performed. Tracing does not authorize a tool or create an
approval. Scope identifiers must still come exclusively from `ExecutionContext`.
For non-HTTP entry points, use `telemetry.request(correlation_id)` with a UUID
generated by the trusted entry point.

```text
http.request
|-- authz.resolve_scope
|-- workflow.<name>
|   |-- retrieval.search
|   |-- retrieval.sufficiency
|   |-- gen_ai.chat
|   |-- tool.<name>
|   |-- approval.<transition>
|   `-- citations.validate
`-- response
```

Middleware produces one server request span and one response span across all
streaming sends. The response is always a direct request child, including when a
workflow initiates streaming. Other spans follow the current context across
`await`; concurrent requests have separate correlation IDs. Only W3C
`traceparent` is extracted. Invalid or duplicate values start a new trace.
The middleware generates a UUID correlation ID, exposes it in ASGI
`state["correlation_id"]`, and returns it in `x-correlation-id`; it does not trust
caller-supplied correlation IDs. Exceptions propagate and set error status/type,
without exporting their message or stack trace. HTTP 5xx sets error status.

## Attribute contract

For defense in depth, `Telemetry.create(service_name, adapter,
sanitize_attributes=callback)` and `start_application_insights(settings,
sanitize_attributes=callback)` accept `AttributeSanitizer`, a callable from
`Mapping[str, AttributeValue]` to `Mapping[str, AttributeValue]`. The public
`SanitizingSpanExporter(exporter, callback)` applies it to span attributes and
each event's attributes on copied `ReadableSpan`/`Event` objects before the
underlying exporter receives a batch. Original spans are not mutated; lifecycle
and failure results are delegated. A sanitizer failure never falls back to
exporting the unsanitized batch. Inject the security package's sanitizer at the
composition root; this package does not import it or define its redaction policy.
This hook is not a license to capture content. It does not sanitize resources,
span/event names, link attributes, or status descriptions; the tracing API avoids
untrusted content in those fields.

| Attribute | Type | Meaning |
| --- | --- | --- |
| `fde.correlation_id` | string (UUID) | Trusted entry-point ID, inherited by all request spans |
| `fde.duration_ms` | float | Wall-clock operation duration; SDK start/end timestamps are also present |
| `fde.retrieval.filter_fields` | string array | Filter **field names only**, never values or raw filter expressions |
| `fde.retrieval.top_k` | positive integer | Requested maximum result count |
| `fde.retrieval.result_count` | nonnegative integer | Returned result count |
| `fde.retrieval.decision` | enum | `sufficient`, `insufficient`, or `abstain` |
| `fde.retrieval.reason_code` | bounded identifier | Static reason code, never free-form reasoning |
| `fde.tool.risk` | enum | `read`, `write`, or `destructive` |
| `fde.outcome` | enum | `success`, `failure`, `denied`, or `abstained` |
| `fde.citations.count` | nonnegative integer | Number of citations checked; no document/chunk text |
| `fde.citations.valid` | boolean | Citation validation result |

Standard attributes: `http.request.method`, `http.response.status_code`,
`error.type`, `service.name`, `gen_ai.operation.name` (`chat`),
`gen_ai.request.model`, `gen_ai.usage.input_tokens`, and
`gen_ai.usage.output_tokens`. Span names and metadata identifiers are bounded
ASCII identifiers. Use static names, not user-generated identifiers.

`SpanAttributes` is a strict, immutable, extra-forbidden Pydantic contract. It has
no prompt, response, document, tool-argument, raw-filter, credential, URL, header,
or baggage fields. There is no content-capture opt-in. Do not bypass the contract
by setting arbitrary attributes/events on returned OpenTelemetry spans, and do
not attach auto-instrumentors that capture content without a separate privacy
review. Request bodies and query strings are never inspected. Application logs
are not automatically exported. This package supplies tracing, not the broader
metrics/evaluation reporting pipeline.

## Verification

Run `uv run --all-packages pytest packages/observability_core/tests` (use native
path separators on Windows), followed by `make check` and `make eval-smoke`.
The root scaffold's default pytest paths do not include package-local tests;
run the targeted command explicitly. Tests verify exact parent IDs, one trace,
GenAI metadata, concurrent isolation, W3C propagation, streaming, privacy on
failures, batch export, managed-identity construction, and credential cleanup.

The Application Insights SDK constructor and batch export path are covered
without network access. A deployed smoke test additionally requires an
Application Insights resource and managed identity: send an instrumented request,
flush, and locate `http.request` and its children under the same operation ID in
Application Insights transaction search. Local tests do not claim portal
visibility or Azure RBAC verification.
