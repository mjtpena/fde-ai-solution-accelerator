# Workspace handbook

This handbook describes how a team shares documents, requests access and keeps
records tidy. It is sample content for the end-to-end ingestion tests and is not
specific to any organisation or industry.

## Requesting access

Access to a shared workspace is requested through the service desk. A request
names the workspace, the reason access is needed and how long it is needed for.
A workspace owner reviews each request within two working days. Access granted
for a fixed period ends automatically; the owner receives a reminder one week
before it does.

Temporary access for visitors is limited to read-only permissions and expires
after fourteen days. Visitors never receive permission to share documents onward.

## Storing documents

Every document has exactly one owner. Owners keep the current version in the
shared library and remove personal copies once the shared version exists. Files
larger than twenty megabytes are stored in the archive area instead of the
library, and are linked from the library page that needs them.

Document names start with the date in ISO format, followed by a short title,
for example `2026-03-14 quarterly planning notes`.

```text
# This line is inside a code block, so it is not a heading.
library/
  2026-03-14 quarterly planning notes.md
```

## Retention

Working notes are kept for twelve months after their last change. Decision
records are kept for six years. When a retention period ends, the owner receives
a notice and has thirty days to extend it with a reason; otherwise the document
moves to the deletion queue, where it stays for a further thirty days before it
is removed permanently.

## Getting help

Questions about this handbook go to the workspace owners' channel. Urgent access
problems outside working hours go to the on-call contact listed on the intranet.
